# Cindy CLI 提供端：开发工作约定

本约定适用于 Cindy CLI 远程 Agent 提供端改造。实施范围见[规划](cindy-cli-plan.md)，实际完成情况见[进度](cindy-cli-progress.md)；约定本身不代表通过技术验收。

## 目标边界

将作为远程能力提供端的 Cindy 客户端无界面化，保留现有官方认证、Device Link、供应商与 Harness 链路；用户电脑上的 Cindy 继续管理项目并执行本机工具。它不是重建官方后台，也不是 SSH 远程工作区。本阶段暂不考虑 Docker。

技术方案、阶段与具体修改清单另写规划文档，未完成论证的内容不得当作已实现能力。权限默认配置须在规划中明确；最高执行权限不等于跳过设备身份、供应商授权或自动回答需求问题。

## 主 Agent 与子 Agent

- 主 Agent 负责架构与计划、稳定任务编号、依赖排序、调度、集成审查、最终验证和文档维护。
- 子 Agent 负责具体实现与定向验证，返回修改文件、行为变化、验证结果、风险及未完成项。
- 模型与推理强度按用户在执行环境中的约定使用，区分请求配置与实际配置；不能确认或无法切换时明确说明，不冒称已满足，不静默替换。个人模型偏好维护在本地复杂任务技能中。
- 子 Agent 不直接并发修改规划与进度台账，由主 Agent汇总，避免状态相互覆盖。

## 规划与进度

实施使用两份互链文档：[规划](cindy-cli-plan.md)与[进度](cindy-cli-progress.md)。

规划记录目标、非目标、源码证据、接口与架构、风险、阶段、任务依赖、预计修改范围、验收标准及验证方法。任务使用稳定编号，例如 CLI-001。

进度按同一编号记录状态、负责人和文件责任范围、实际改动、验证命令及结果、阻塞、偏差和下一步。状态统一为：待开始、进行中、待验收、已完成、阻塞。

子 Agent 报告完成后先记为待验收；主 Agent 检查整体 diff 并完成适用验证后才能记为已完成。验证失败、环境故障与未验证项目必须如实登记。

## 执行循环

1. 主 Agent 检查当前工作区、规则、代码与测试，维护规划。
2. 从依赖已满足的任务中选择工作，向子 Agent 明确接口、文件范围、验收标准和验证要求。
3. 子 Agent 实现并提交结果；主 Agent 集成审查，执行适用验证。
4. 更新进度，对照规划逐项检查遗漏、回归和未满足的验收；发现问题继续委派。
5. 所有授权范围内的任务通过验收且文档与实现一致后结束。

每批委派、验收、计划调整及暂停前保存文档。恢复工作时对照文档和实际 diff，不重复已完成工作。计划调整必须记录原因与影响，不能删除未完成项来制造完成。

## 并发执行

互不依赖、文件写入范围不冲突的功能允许多个子 Agent 并发实现，遵守用户和宿主资源预算，不固定并发数量。

共享接口先明确；存在前置依赖则先完成前置任务。每个并发任务指定唯一写入范围，同一文件原则上只由一个 Agent 修改。共享端口、数据库和运行服务必须隔离或排队。主 Agent 统一解决接口与集成问题，不回退或覆盖其他任务改动。

## 阻塞与完成

外部条件缺失、模型配置不可用或需要新增授权时，记录阻塞证据、影响与恢复步骤，继续独立任务，不把阻塞记成完成，也不无限重试。

遵守仓库的凭证、权限、协议与数据专项规则。本约定不额外授权提交、推送、发布、部署或破坏性操作。

完成时逐项给出验收证据和剩余风险，链接规划与进度文档；代码存在、单个子 Agent 完成或单测通过，均不独立等同于整体交付完成。
