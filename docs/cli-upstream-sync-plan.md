# CLI 官方更新同步计划（2026-11-13）

## 目标与边界

以当前源码为基线，修复 cindy-host 与新版官方 Desktop 交互涉及的远程轮次生命周期、
Codex 额度读取和 Claude 运行时兼容问题。每项先确认生产路径与最小失败输入，再实现和验证。

- 当前运行实例保持不动：不停止、不重启、不重建或替换容器、镜像、已安装二进制、部署产物与配置。
- 不使用真实账号、凭证或模型额度；不修改服务端，不提交、推送、合并或发布。
- 用户最终限定只检查 CLI：停止 Desktop 类型检查，不再运行 Desktop 或整仓检查；
  已完成的相关回归保留记录，Desktop 完整类型检查明确标为未完成。
- 不在本轮新增 Agent-Net、多账号池、模型组或 UI 功能；不把源码适配称为线上互通已验收。
- 上游参考固定为 `8d65e21e521b928a04b31302be0ab66440780f80`；稳定发布与该主干快照分开判断。
  稳定版为 0.1.135，0.1.136-beta 为预发布；不直接整体覆盖上游目录。

## 当前源码证据与架构

CLI 从 `apps/cindy-host/src/runtime/index.ts` 接入 `packages/remote-agent-host`，
Desktop 相关入口部分重导出共享包；官方上游仍在 Desktop remote-agent 目录修复。
迁移必须落入真正被 CLI 调用的实现，并检查 Desktop 的消费侧。

Codex 额度由 CLI provider 调用 maker-core 的 `readAccountRateLimits`，原生 RPC 超时应在
app-server 请求层收口，不另建 UI 等待计时器。Claude pin 当前为 2.1.312，固定上游为
2.1.321；Codex 双方均为 0.159.2。

开始新计划时已有本轮未提交草稿；这些改动全部重新审查，不作为已完成依据。

## 风险与未决问题

1. 生命周期补丁跨 Session、宿主与代理，不能只复制一个状态机文件；已有草稿存在缺失接口和未完成的
   idle-drain 顺序修复，必须完整验证后才可交付。
2. Claude 上游调整 `DISABLE_TELEMETRY` 默认值来恢复模型 feature flags，涉及默认隐私行为。
   本计划不直接采纳该变化：先核对规则与实际必要性，明确能否保持现有隐私默认而兼容新版。
   若必须改变默认行为，单独提出具体方案，不混入普通版本 pin 更新。
3. 不新增 wire 字段、授权范围或 relay 行为是本轮预期边界；实现若必须越界，先更新方案与风险说明。
   旧端未知字段和错误处理需检查，不能仅凭本地类型通过断言兼容。
4. 恢复故障半径为单个 run / 请求；不重建共享 relay。以多 run / peer 回归验证其它任务保持可用。
5. 本轮不操作部署。后续真实双端、账号登录、分享撤销与断线恢复验收需要另行安排，
   未完成前只交付经过本地验证的源码。
